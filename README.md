# Durbin Films website

Static site for Durbin Films, a television drama and web series production house in Dhaka.
Built with Next.js 15 (App Router, static export), TypeScript, Tailwind CSS v4 and Framer Motion.

## Run it

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # writes the finished site to out/
npm run preview    # serves out/ locally
```

`npm run build` produces plain HTML, CSS and JS in `out/`. Upload that folder to any static host
(Vercel, Netlify, Cloudflare Pages, GitHub Pages, an S3 bucket, shared hosting).

## Routes

| Route           | Source                         |
| --------------- | ------------------------------ |
| `/`             | `app/(en)/page.tsx` (DURBIN FILMS dramas only) |
| `/work/`        | `app/(en)/work/page.tsx` (every production, grouped by channel) |
| `/founder/`     | `app/(en)/founder/page.tsx`    |
| `/work/<slug>/` | `app/(en)/work/[slug]/page.tsx` |
| `/bn/...`       | `app/(bn)/bn/...`, the same four pages in Bangla |

Each route file is a few lines that render a view from `components/views/` in one language, so
English and Bangla always share the same layout. See "Bangla site" below.

## Content lives in three JSON files

- `content/works.json`: one entry per production. This is the only place productions are defined.
- `content/founder.json`: everything on the founder page.
- `content/site.json`: studio name, contact details, social links, default Open Graph image.

There are four content files: the three above plus `content/home.json` for the home page copy.
Anything still in square brackets is a placeholder; search the files for `[` to find what is left.

### Adding a production

1. Add an entry to `content/works.json`:

```json
{
  "slug": "my-new-drama",
  "title": "My new drama",
  "type": "drama",
  "year": "2026",
  "channel": "Channel name",
  "platform": "",
  "client": "",
  "episodes": 1,
  "badge": "EID SPECIAL",
  "synopsis": "Two or three sentences.",
  "poster": "/images/posters/my-new-drama.jpg",
  "backdrop": "/images/backdrops/my-new-drama.jpg",
  "youtubeId": "dQw4w9WgXcQ",
  "featured": false,
  "credits": [{ "role": "Director", "name": "Name" }],
  "gallery": ["/images/gallery/my-new-drama-1.jpg"]
}
```

2. Drop the poster (2:3, at least 800x1200) and backdrop (16:9, at least 1920x1080) into
   `public/images/posters/` and `public/images/backdrops/`.
3. `npm run build`.

Rules the pages follow:

- `type` is one of `drama`, `series`, `brand`, `short`, `documentary`, `song`.
- Home page rails, in order: dramas whose `platform` is `DURBIN FILMS`; natoks and serials from the
  other channels; short films; songs. `/work/` lists everything again, one section per channel with
  search and filters. Entries keep file order within a rail or section. All of this is set in
  `app/page.tsx` and `app/work/page.tsx`.
- `featured: true` puts an entry in the home hero. Keep those to DURBIN FILMS titles so the hero
  matches the rail beneath it.
- `titleBn` (optional) is the title in Bangla script, shown under the Latin title on the detail page.
- `views` (optional) is the public view count as YouTube shows it, e.g. `"41M"`. It appears as a
  chip on the poster, in the details grid, and in the hero line when there is no synopsis yet.
- `poster` and `backdrop` are local files under `public/images/`. `npm run art` downloads each
  production's YouTube thumbnail once, converts it to WebP at the size actually displayed and
  rewrites `works.json` to point at the local copy, which keeps the artwork off the critical path.
  Entries still using a full https URL are fetched the next time it runs. `"posterFit": "thumb"`
  sits a 16:9 image whole inside the 2:3 poster frame over a blurred copy of itself; drop a real
  2:3 poster in and remove that key to switch.
- `youtubeId` is the trailer. When it is empty but `watchUrl` is a YouTube link, the play button
  says "Watch now" and plays the full video instead. `trailerStart` (seconds) offsets the trailer.
- The line under a poster is the first non-empty of `channel`, `platform`, `client`, then the year.
- The optional `hero` object overrides the kicker, chip, meta line and blurb on the home hero;
  leave it out and sensible text is derived from `type`.
- `credits` and `gallery` are optional and only show on the detail page.

## Images

Placeholder art is generated by `npm run placeholders`. It only writes files that are missing, so
real photos are safe; pass `--force` to regenerate everything. Replace any file with a real image of
the same name and ratio:

| Folder                     | Ratio | Suggested size |
| -------------------------- | ----- | -------------- |
| `public/images/posters/`   | 2:3   | 800x1200       |
| `public/images/backdrops/` | 16:9  | 1920x1080      |
| `public/images/gallery/`   | 16:9  | 1600x900       |
| `public/images/founder/`   | 4:5 portrait, 16:9 backdrop |   |
| `public/images/studio/`    | 4:5   | 1200x1500      |
| `public/og-image.png`      | 1200x630, generated by `npm run og` | |

The site is exported statically, so images are served as-is. Export JPEGs at around quality 75 and
keep backdrops under 300 KB for a fast first paint.

## Home page copy

All of the home page's brand copy lives in `content/home.json`: the hero headline, the marquee
items, the four process steps, the three service tiles, the studio paragraphs, the questions and
answers, and the contact CTA. Edit that file and rebuild; no component needs touching.

The questions in `home.json` under `faq` are also emitted as `FAQPage` structured data, so keep
them phrased as real questions a client would type into Google.

## Keeping up with YouTube

```bash
npm run sync        # refresh views, release dates and running times; list new uploads
npm run sync:dry    # same, without writing works.json
```

The sync looks up every production's video (from `watchUrl` or `youtubeId`) and updates `views`,
`released` and `durationSeconds`. It then reads the RSS feed of each channel in `site.json`'s
`youtubeChannels` and prints uploads that are not on the site yet, with their links, so you can add
the ones you want to `works.json`. Anything released in the last six months gets a NEW tag on its
poster automatically. Run the sync before a build, or wire it into a weekly automatic build on
your host.

## SEO

Every page has its own title, description, canonical URL, Open Graph and Twitter tags. Structured
data (JSON-LD) is generated from the content files:

- root layout: `Organization` and `WebSite` with a `SearchAction` pointing at `/work/?q=`
- home: `ItemList` of the DURBIN FILMS dramas
- founder: `Person`
- `/work/`: `CollectionPage` with an `ItemList` and breadcrumbs
- each production: `Movie`, `TVSeries` or `MusicVideoObject`, plus a `VideoObject` (thumbnail,
  upload date, duration, embed URL, view count) so Google can show a video result, plus breadcrumbs

`sitemap.xml`, `robots.txt` and `manifest.webmanifest` are generated at build time. Put your Search
Console token in `googleSiteVerification` in `site.json` to add the verification meta tag.

Share images are built by `npm run og` (scripts/make-og.mjs) with sharp, no external service:
`public/og-image.png` at 1200x630 for Open Graph and Twitter, and `public/og-image-square.png` at
1200x1200 for platforms that crop square. The logo comes from `public/images/brand/logo.png` and the
line of copy is set in Plus Jakarta Sans from `scripts/assets`, the site's body face. Social
platforms cache previews, so after changing the image use Facebook's Sharing Debugger to scrape
the page again.

## Bangla site

Every page also exists in Bangla under `/bn/` (`/bn/`, `/bn/work/`, `/bn/founder/`,
`/bn/work/<slug>/`), so the studio can be found by people searching in Bangla, for example
দুরবীন ফিল্মস, বাংলা নাটক or a natok's Bangla title. The brand is written দুরবীন ফিল্মস, the same
way Durbin News writes দুরবীন.

- `content/bn/home.json` and `content/bn/founder.json` hold the Bangla copy, in the same shape as the
  English files. The founder file only carries text; images and profile links come from
  `content/founder.json`.
- `content/bn/site.json` holds the Bangla name, title, description, address and the search keywords.
  The keywords ending in ফিল্মস are also written into the Organization structured data as
  `alternateName`, on both languages.
- `content/bn/works.json` holds a Bangla `synopsis` (and optional `hero`) per production, keyed by
  slug. A production with no entry gets a generated Bangla line from its cast and views.
- On Bangla pages the production's `titleBn` is the title; the Latin title is kept in the
  structured data only. Add a `titleBn` to every new production in `works.json`.
- `content/bn/names.json` holds the Bangla spelling of every name in the credits (`people`) and of
  the social link labels (`links`). A name missing from it shows in Latin letters on the Bangla
  page, so add the cast and crew of each new production there.
- Interface strings (buttons, labels, credit roles, badges, channel kinds, channel names) are in
  `lib/i18n.ts`.
  Numbers are shown in Bangla digits there, and view and subscriber counts in লাখ and কোটি.

Each pair of pages links to the other with `hreflang` (English is `x-default`), the sitemap lists
both with their alternates, and the nav has a বাংলা / English switch. The two languages have their
own root layouts (`app/(en)/layout.tsx`, `app/(bn)/layout.tsx`) so `<html lang>` is right in the
static HTML; because of that the 404 page is `app/global-not-found.tsx`. Bangla text is set in Hind
Siliguri, which only downloads on English pages when a Bangla title is on screen.

When you add a production, add its Bangla synopsis to `content/bn/works.json` as well.

## Contact details

`content/site.json` holds the studio address, email, phone, social links, and the founding
(`founded`) and registration (`registered`) dates, both 1 July 2022. `phone` is the
dialable number used in `tel:` links; `phoneDisplay` is what visitors see. Every entry in `social`
with a link is shown in the home page FOLLOW list; the founder page shows his own
profiles from `founder.json` under `contact.links`.

## Deploying

The site is hosted on Vercel, connected to this repository. Every push to `main` triggers a build
and deploy; pull requests get their own preview URL.

Vercel settings (its Next.js preset detects these automatically):

| Setting          | Value           |
| ---------------- | --------------- |
| Framework        | Next.js         |
| Build command    | `npm run build` |
| Output directory | `out`           |

`next.config.ts` sets `output: "export"`, so the build produces a fully static site with no server
behind it. Any other static host works the same way: run `npm run build` and upload `out/`.

For the durbinfilms.com domain, add it in the Vercel project under Settings, then Domains, and
point DNS at the records Vercel shows you.

## Before going live

- Confirm `url` in `content/site.json` is the live domain. It drives canonical URLs, Open Graph
  URLs, the sitemap and JSON-LD.
